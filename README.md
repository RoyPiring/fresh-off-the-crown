> *Does this capability earn a place in how I actually work? A decision log with a build attached.*

The AI tooling landscape ships more good news than any working engineer can act on. This is the filter I run so that keeping current stays a habit instead of a second job. Every build answers that one question about one capability, and the build exists to make the answer honest, because a verdict formed by reading is a guess and a verdict formed by running is evidence.

More land here as I build them, one at a time.

## What it covers

Capabilities inside tools already in daily use, plus the vendor-independent parts that outlast any one of them: what a run costs, what goes in the context window, how you know an agent got better, orchestration shape, tool contracts, and failure modes. Every build points at a real friction with a measured before, ends in exactly one verdict of adopt, reject, watch, or park, and carries a reversal trigger naming what would change the decision.

**What it isn't.** Not a tutorial collection and not a newsletter. Benchmark leaderboards, funding news, and anything sourced only from a thread stay out, because they match no friction and change nothing about how the work gets done. Nothing needing a metered key or a card is used, so a daily habit never carries a daily cost.
